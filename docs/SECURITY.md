# 安全性：驗證了什麼、沒辦法保證什麼

最後一次完整審查：2.10.4。方法與結果如下；任何一項都可以用文中的指令重現。

## 威脅模型

| 誰 | 想做什麼 | 防線 |
|---|---|---|
| 沒帳號的人（拿到公開金鑰） | 讀資料、自行註冊、呼叫管理功能 | 所有資料表鎖死（RLS＋沒有權限）；註冊被資料庫觸發器擋掉；管理函式沒有匿名執行權；雲端函式驗 JWT |
| 學員 | 看別人的進度、提升自己的權限、改授權、繞過 IP／期限、無限用 AI | 只能呼叫會驗身分的函式；所有 `admin_*` 都先驗管理員；授權由伺服器重算；AI 有每日／每月上限與輸入長度上限 |
| 同一台電腦上的其他程式／網頁 | 偷 token、打本機 API、DNS rebinding、CSRF | 只綁 127.0.0.1；每個請求驗 token、Host、Origin；嚴格 CSP |
| 被入侵的雲端／共用資料夾 | 透過同步寫入學員電腦的任意檔案 | 同步只接受 `solutions／tests／statements` 底下的檔案，其餘一律忽略 |
| 學員資料被拿去做 CSV 攻擊 | 在姓名／備註放公式，管理員用試算表開啟時執行 | 匯出的 CSV 對 `= + - @` 開頭的欄位加單引號 |

## 驗證方法（可重現）

1. **資料庫權限矩陣**：查 `pg_proc`／`information_schema` 確認——匿名只能執行 `app_info()`；登入者對資料表只有 `profiles` 的 SELECT（RLS：只看自己的列）；27 個函式中 19 個 `admin_*` 的原始碼都呼叫 `_need_admin()`；所有 security definer 函式都固定了 `search_path`；`access_for()` 只有 service_role 能執行；`app_secrets` 對任何前端角色沒有任何權限。
2. **匿名攻擊**：對每張表嘗試讀、新增、修改、刪除；對 10 個函式嘗試呼叫；對兩個雲端函式用「只有公開金鑰」「沒有授權標頭」「偽造 JWT」呼叫；嘗試註冊與呼叫 Auth 管理端點——全部被擋（401／403 或註冊觸發器拒絕）。
3. **本機伺服器探測**：`python dev/security_probe.py`（74 項，CI 也會跑）：未登入存取 15 個 GET、14 個 POST；11 種路徑變形（`//api`、`/API`、`%2f`、`%00`…）；錯 token、錯 Host、錯 Origin、非 JSON、超大 Content-Length；8 種目錄穿越；學員越權呼叫管理 API；登入憑證檔權限；登出後再次被擋。
4. **自動化測試**：`tests/test_cloud.py`（離線寬限、時鐘回撥、閘門、同步路徑限制、密碼規則）。
5. **Supabase 安全顧問**：剩下的提示都是設計上刻意的（有 security definer 函式；資料表沒有 policy 是因為只允許經函式存取）。

## 這次審查修掉的問題

- 雲端／共用資料夾同步可以寫入 `solutions／tests／statements` 以外的路徑（例如 `.cpe/cloud.json`）→ 現在只接受那三個資料夾。
- 管理員的 CSV 匯出沒擋公式注入 → 已加。
- `ai-proxy` 沒有輸入長度上限，學員可以用超長輸入燒額度 → 上限 40 則訊息、6 萬字元。
- 建立帳號時姓名、班級沒有長度限制 → 函式端截斷＋資料庫 check 限制。
- 管理員「完整備份」會匯出每位學員的完整學習資料（含程式碼）→ 改成只匯出摘要。

## 沒辦法由程式保證的（請你知道）

1. **程式在學員電腦上。** 會寫程式的人能改掉本機的檢查；伺服器保護的是進度、AI 與金鑰、名單，不是題目內容。`cpe` 指令列不受登入限制。
2. **有些設定只能在 Supabase 後台做，我的工具改不了**：關閉「Allow new users to sign up」（目前已由資料庫觸發器擋住，這是第二道鎖）、開啟 Leaked password protection、提高密碼最短長度（伺服器端目前是 Supabase 預設的 6 字；8 字規則只在本機介面強制，直接呼叫 Auth API 的人可以繞過）、調整登入頻率限制。
3. **登入失敗沒有鎖帳號機制**，只有 Supabase 內建的頻率限制。
4. **登入憑證（refresh token）存在 `.cpe/cloud.json`**：Unix 上權限 600；Windows 沒有同等保護，靠使用者目錄的存取權限。不進備份。
5. **每日 AI 額度檢查與計次之間有小競爭視窗**：同時送出的請求可能超過上限幾次。
6. **雲端進度上限**：每位學員 12 MB；200 位全部用滿約 2.4 GB，超過免費方案的 500 MB 資料庫。實際用量遠小於此，但請留意容量。
7. **隱私**：管理員（以及有資料庫權限的人）可以看到學員同步上來的完整學習資料，包含解題程式碼。請在使用前告知學員。
8. **公開的 publishable key 寫在 `cpe_coach/data/cloud.json`**：這是設計上公開的；絕對不要把 service_role 金鑰放進任何程式碼。
9. **IP 限制是提高門檻**：VPN／代理會換掉 IP。
10. **這次沒有做**：滲透測試公司等級的審查、對 Supabase 平台本身的審查、真的 OpenAI 金鑰的端對端測試。
