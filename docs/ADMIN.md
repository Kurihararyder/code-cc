# 管理員手冊（靜宜大學 晶片設計學士學位學程 · CPE 練功系統）

登入後，左下角的「人員」按鈕 → **管理後台**（只有管理員看得到）。

## 第一次使用

1. 用管理員帳號登入（學號 `admin`）。第一次登入必須改密碼。
2. **AI 與金鑰**：貼上 OpenAI API 金鑰 → 儲存 →「測試呼叫」。金鑰只存在資料庫（`app_secrets`，沒有任何前端可讀的權限），學員的電腦拿不到。
3. **授權與網路**：設定 IP 限制與離線寬限（見下）。
4. **學員帳號** → 批次新增：貼上「學號, 姓名」（可從 Excel 貼兩欄），設定班級、授權期間，下載初始密碼 CSV 發給學員。學員第一次登入必須改密碼。

## 各分頁

| 分頁 | 功能 |

| 學員帳號 | 搜尋／依班級、狀態篩選；多選後批次：啟用／停用、授權期間、延長 N 天、開放／關閉 AI、IP 限制、班級；單人編輯（姓名、班級、備註、授權起訖、IP 模式與清單、AI）、重設密碼、刪除；看每人學習進度（已解題數、單元、活躍天數、最後學習）；匯出 CSV |

## 備份與封存

- 總覽右側「匯出完整備份」下載 JSON（名單、設定、進度、稽核紀錄；不含金鑰與密碼）。Supabase 免費方案沒有自動備份，建議每學期或每月匯出一次。
- 學期結束用「封存」而不是刪除：帳號停用並從清單隱藏，資料保留，可從「已封存」篩選還原。

## 授權怎麼判斷（每次登入、每 10 分鐘、每次 AI 呼叫都由伺服器重算）

1. 帳號必須「啟用」。
2. 現在時間要在「授權開始 ～ 授權結束（含當天）」之內；空白表示不限。
3. IP：個別帳號的模式——
   - **跟隨全域**：全域 IP 限制關閉就不限；開啟就必須在全域清單內。
   - **不限制**：任何 IP。
   - **只允許下列 IP**：帳號自己的清單。
   - 管理員不受 IP 與授權期間限制（避免把自己鎖在外面）。
4. AI：需要總開關開啟、該帳號被授權、沒超過每日次數、資料庫裡有金鑰。

**IP 由伺服器判斷**（Cloudflare 的 `cf-connecting-ip`），學員無法自報或偽造請求標頭。但 VPN／代理會換掉 IP，所以 IP 限制是「提高門檻」，不是絕對防線。

## 離線

學員斷網時，使用「上一次伺服器確認通過」的結果，最多撐「離線寬限」小時（預設 72），而且不會超過授權結束時間。系統時鐘被往回調會被拒絕。**第一次使用必須連網。**

## 更新

學員的程式每次開啟（與之後每 30 分鐘）會：① 向資料庫讀最新／最低版本與公告；② 檢查程式有沒有新版本（git 或安裝精靈的更新來源）。有新版本時左下角出現提示，一鍵更新並自動重新啟動；版本低於「最低可使用版本」時，必須先更新才能登入。

發布新版的建議流程：推到 GitHub → 在「版本與公告」把「最新版本」改成新版號 → 等大家更新後，再提高「最低可使用版本」。

## 安全模型（請看這一段）

- 由**伺服器強制**的：誰能登入、授權期間、IP、AI 額度與金鑰、雲端進度的存取（Postgres RLS ＋ 函式）。學員用公開的 anon／publishable key 什麼都讀不到；所有資料表都鎖死，只能經過會檢查授權的函式。
- **沒辦法由伺服器強制**的：程式本身在學員電腦上，題目與測資是隨程式安裝的；會寫程式的人可以改掉本機的檢查、繼續離線練習。要真的保護題目，需要改成登入後才從伺服器下發題目（目前沒有這樣做）。
- 學員電腦上只有：publishable key（設計上就是公開的）與自己的登入憑證（`.cpe/cloud.json`，權限 600，不進備份）。`service_role` 金鑰從來不在程式裡，只存在 Edge Function 的環境中。
- 自行註冊已被資料庫擋掉（只有管理員建立帳號的短暫期間才能新增使用者）。建議再到 Supabase 後台 Authentication → Sign In / Providers，關閉「Allow new users to sign up」。
- 本機 CLI（`cpe` 指令）不受登入限制；登入閘門只管網頁介面（也就是學員實際使用的介面）。

## 遺失管理員密碼

到 Supabase 後台 → Authentication → Users，找到 `admin@icd-cpe.example.com` 重設密碼，然後在 SQL Editor 執行：`update public.profiles set must_change_pw = true where student_id = 'admin';`
